AI chat widget with configurable providers, page context, a local knowledge index, and appearance settings.

== Description ==

WLN Multi-Provider AI Chat adds a floating chat widget to a WordPress site. Site administrators choose an AI endpoint and model, supply credentials, and configure the widget. Replies are generated by the configured service.

Features include:

* OpenAI, Anthropic Claude, Google Gemini, YandexGPT, OpenRouter, local Ollama, and custom OpenAI-compatible endpoints.
* A local database knowledge index for published public posts, pages, and administrator-supplied Markdown documents.
* Optional page context and configurable conversation history sent with a question.
* Widget colors, dimensions, position, fonts, and welcome messages.
* Signed visitor sessions, abuse-prevention rate limits, encrypted API-key storage, and administrator permission checks.
* Local conversation statistics, configurable retention, and visitor-controlled history deletion.
* Translation-ready interface and integration with Polylang for saved widget strings. Translations are distributed through translate.wordpress.org.

All included plugin features are available without a plugin license or subscription. External AI providers may require accounts and charge for their processing. Request limits protect the site from abuse; they do not unlock paid plugin features.

This is an independent plugin and is not affiliated with the listed AI providers.

== Installation ==

1. Upload the plugin ZIP through Plugins > Add New > Upload Plugin and activate it.
2. Open AI Chat > API Settings. Review the external-service disclosures below, then choose an endpoint and model and enter the provider's API key. For a local Ollama endpoint that ignores authentication, enter a non-empty placeholder such as `ollama`.
3. Click Test Connection, then save the settings.
4. Configure Widget Settings and optionally add Markdown documents under Knowledge Base.
5. Update the site's privacy notice to describe chat storage and the chosen provider. The floating widget appears on the frontend.

The floating widget is configured through Widget Settings. Existing `[gsxr_777_chat]` shortcodes and the new `[wln_multi_provider_ai_chat]` alias remain recognized; the frontend displays one global floating widget.

== External services ==

No provider request is made merely by activating the plugin or opening the widget. After the administrator configures the service, requests are made when a visitor sends a message or an administrator clicks Test Connection. The connection test sends a fixed test message through the same prompt-building process, so configured system instructions and any relevant knowledge excerpts may also be included.

Requests contain the API credential, selected model and generation parameters, system instructions, the current message and a limited conversation history. Relevant knowledge excerpts may be included. If page context is enabled, the current page URL, title, content excerpt and selected text may also be included. Yandex requests additionally include the configured project/folder identifier. The provider sees the server's network address and HTTP request metadata. Visitor IP addresses and browser user agents are not deliberately included in AI prompt payloads.

Only the configured endpoint receives these requests. Asynchronous Yandex generation may require follow-up status requests. There is no developer telemetry, advertising tracker or license-verification service. Provider documentation links are ordinary links and open only when clicked.

= Ollama and custom endpoints =

The Ollama preset uses http://localhost:11434/v1 on the WordPress server. The same request data is sent to that local service on chat and test requests. The plugin does not contact ollama.com automatically. Whether an Ollama model or a custom gateway forwards data elsewhere depends on how the administrator configures that service.
Ollama service terms: https://ollama.com/terms
Ollama privacy: https://ollama.com/privacy
Local Ollama software license: https://github.com/ollama/ollama/blob/main/LICENSE

For a custom endpoint, the destination and applicable terms/privacy policy are determined by the administrator. Review those documents before configuration and disclose that service in the site's privacy notice. The plugin cannot identify the operator or terms of an arbitrary URL.

== Frequently Asked Questions ==

= Where is chat data stored? =

Conversation messages and local statistics are stored in this site's WordPress database. A signed conversation credential is stored in the visitor's browser local storage so the conversation can resume after page reloads. Visitors can clear their history. Retention and optional request metadata are configurable in API Settings.

= Will an update reset my settings? =

No. Existing option names, database tables, encryption derivation, browser session storage and the legacy shortcode are retained for compatibility. Defaults are added only for missing options. A fallback imports options from partially renamed builds only when the original option does not exist. Deactivation does not delete settings.

The first change from the old plugin directory/main filename to the new slug requires manual activation of the new plugin. Back up the site, deactivate the old plugin, install and activate this package, then check the existing configuration. Do not activate both copies together. Do not use WordPress's Delete action on the old copy if its data-removal option is enabled, because both copies share stored data. A slug change does not automatically become a normal WordPress update.

= Does this use the WordPress AI Client? =

This release retains direct provider integrations to preserve existing credentials, model parameters, custom endpoints and support for WordPress versions before 7.0. It does not automatically migrate provider settings into the core AI Client.

= Are there private REST endpoints? =

The session endpoint issues a new random signed credential without storing data or contacting an AI provider. Configuration and translated-label endpoints intentionally expose only frontend widget settings. Chat and history endpoints require the conversation's signed credential. Administrative operations require manage_options and form/AJAX nonces when changing data.
